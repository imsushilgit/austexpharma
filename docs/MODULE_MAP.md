## How paths now work

* Includes: `require_once __DIR__ . '/../includes/core.php';` (same pattern in every module page).
* Links between modules inside a page: relative, e.g. `../hr/leave.php`; links inside the same folder stay as `leave.php`.
* Shared files in `includes/` (sidebar, header, core) build links with `BASE_URL` (`/salesmgmt/`, defined in `includes/core.php`), e.g. `<?= BASE_URL ?>hr/leave.php`.
* `core.php` still looks for `config.ini` in the project root, then one level above it, and still writes `system_errors.log` one level above the project (same physical locations as before).
* Uploads: `settings.php` and `form16.php` still save into the root `uploads/` folder; saved links are prefixed with `BASE_URL` so they open from any module folder.

## `assets/css/style.css` – The single stylesheet (no `<style>` blocks in any PHP file)

* **One file** for the whole application. Sections inside it, in order: shared base/sidebar/theme, then one section per page, then the `pro` theme.
* `includes/header.php` links it (`<?= asset_css('style.css') ?>`, helper in `includes/core.php`, adds a `?v=<mtime>` cache-buster) and sets the body class `app pg-<folder>-<file>`.
* Standalone pages without the app shell (login, logout, print/receipt/slip/letter pages, invoice verify) link it with a plain `<link href="../assets/css/style.css">` and carry their own `pg-...` body class.
* **Page rules are scoped** to their page: e.g. `body.pg-accounts-outstanding .compact-table {...}`. The same class name on two pages therefore never clashes. To restyle one page, edit its section (search for its file name in the comments).
* Shared rules are scoped to `body.app`.
* Cascade layers: `base < sidebar < components < page < pro`. The final `pro` layer (compact spacing, 1px dotted table borders) always beats page rules.
* Borderless layout table: `class="plain-table"` or inline `border:none`.
* `hr/hrletters_print.php` chooses its letter template with body classes `tpl-modern | tpl-classic | tpl-minimal`.
